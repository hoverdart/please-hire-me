# Capability matrix

This table separates what the worker implements from what has been observed at an employer. It is generated from `hireme/capabilities.py`, which also feeds the dashboard's coverage view and `hireme capabilities`. A test keeps this page and the code identical.

**Levels.** *Implemented*: built and exercised by local fixtures. *Partial*: built, with the stated gaps. *Gated*: present but off until separately commissioned. *Manual*: handed to the applicant. *None*: not built, or no evidence.

**Reading the last two columns.** Local fixture coverage is synthetic evidence from this repository's own test servers. Live validation lists employer-side evidence for specific postings on specific dates. Neither certifies a platform: a recognized host, a passing fixture and one accepted application all leave other employers' forms unverified.

## What changes a cell

- A fixture cell changes when a synthetic end-to-end test for that behaviour is added or removed.
- A live cell changes only after a legitimate, eligible application through the ordinary worker returns the adapter's correlated acknowledgement and a fresh receipt. Record the date and scope here; keep the posting, screenshots and receipts in private storage.
- An uncertain live attempt is evidence too. It stays listed and is never retried to improve the table.

## Gates that stay closed

- Staged rollout (`hireme rollout`) commissions Lever and Ashby only. Adding a platform to it needs that platform's own native acknowledgement evidence.
- `allowed_application_ats` treats `icims` as its own scope; allowing `other` does not include it.
- Native Workday, Handshake and Work at a Startup transports stay off until their reviewed, machine-bound flow evidence exists. A sign-in or a setting cannot create that evidence.
- The adaptive executor never writes to account-profile, registration, withdrawal or deletion endpoints, and never opens a frame from another origin or requisition.
