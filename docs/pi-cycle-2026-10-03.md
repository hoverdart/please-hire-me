## Remaining blockers and repair order

1. **Date and state answer mapping.** The confirmed profile has education start and graduation dates and state `CA`. Required split date controls produce `option_mismatch` or `numeric_answer_needed`; the state selector offers `California` but produces `option_mismatch`. Date fixes must preserve which education/employment entry a control belongs to; the generic start/end labels alone do not establish that association. Implement deterministic, context-aware date components and state aliases, with fixtures matching these forms.
2. **Missing owner-confirmed answers.** The country and pronouns facts are absent. Affirm's prior-employment selector expects a descriptive option rather than the stored generic yes/no response. Request explicit owner confirmation where necessary, then reuse exact scoped answers. Gender must not supply pronouns. Summer relocation willingness and an earliest start date do not by themselves answer an explicit availability commitment.
3. **Repeat selection and request exhaustion.** Recent ordinary cycles repeatedly attempted the same unanswered postings, with the latest prior cycle reaching the 100-request daily limit. The worker includes blocked jobs and ranks primarily by fit. It does not defer unresolved-question jobs until relevant answers change. Add a retry/defer policy that gives unattempted eligible jobs a chance while allowing answered/changed jobs back into the queue. Increasing the model cap alone does not repair missing required answers.
4. **Other observed constraints, outside this diagnostic sample.** Prior-cycle events identify a Hermeus application-entry adapter failure; owner-specific questions at Netic and Replit; a human work-sample guard at Kastle; and Ashby `not_submitted` results. The implementation recognizes Ashby's explicit possible-spam rejection as `not_submitted`. Those outcomes need employer-visible investigation, not automatic retries or a claim that these three forms reproduce every prior failure.
