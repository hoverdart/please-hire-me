# Application desk

## Surface
A private application workspace for individual applicants. Overview shows the worker state, today's confirmed submissions, distinct opportunities needing attention, and the persisted opportunity ledger. Counts reflect local records; no sample activity appears in the real workspace.

## Direction
Cool paper, white surfaces, deep navy text, restrained blue actions, and compact editorial tables. A narrow desktop sidebar groups the workspace, personal sources, and connections. Small uppercase labels establish hierarchy; generous space keeps forms approachable. A typographic monogram and a CSS document illustration introduce the product without remote assets.

The overview uses three summary cards, searchable and sortable opportunities, plain-language status badges, and an expandable posting form. Search includes company, role, and location. Attention counts deduplicate blocked jobs and their questions. Setup presents a numbered checklist, optional-source labels, and visible guided progress. Preferences are grouped into search, company boundaries, pace, model usage, and browser configuration.

## Tokens and behavior
Background #f4f6f9; surface #ffffff; ink #1c2b40; muted #596a82; rule #e2e8ef; action #285ed5. System typography, 15px base and 1.6 line height. State labels accompany color. Controls have at least 44px height, visible focus, real labels, and live notices. Reduced motion is respected. No external fonts, images, scripts, or styles are required.

On smaller screens the sidebar becomes a scrollable horizontal navigation bar. Summary cards reflow, forms become one column, and table rows become labeled records. The workspace must not overflow at 320px or 390px. Text colors are checked against the actual surface backgrounds. Horizontally scrolling command blocks are keyboard focusable. Browser fixture tests cover uploads, setup, counts, filtering, sorting, posting creation, safe text rendering, preferences, and mobile navigation.

Answer packages load when their evidence disclosure opens. Overview refreshes and ledger pages use narrow application metadata. A bounded memory cache retains up to 100 requested records and 10 viewed confirmation images, keyed by record identity, timestamp, package hash, state and screenshot name. No applicant drafts or evidence enter browser storage. Open evidence and diagnostic disclosures retain keyboard focus across refreshes. The unresolved-outcome queue uses the same on-demand evidence cache and preserves its reading focus. Loading and image failures have local retry feedback; corrupt records are reported instead of being represented as empty answers. The opportunity dialog has a sticky close control for long postings.

Writing-source cards retain their DOM nodes across unchanged refreshes. A compact signature covers source identity, revision, update time, display metadata, original-file availability and active page/filter totals. Unsaved source edits still prevent replacement; a confirmed revision, original-file availability change or page/filter change refreshes the cards. Source library requests serialize with regular polling, preserve the current page on failure and restore keyboard focus after explicit page changes.

Recorded PDF downloads are explicit evidence actions. They send the local dashboard capability in a request header and bind each request to its application ID, document index and expected content hash. Files are verified and captured by the backend before response; current upload selection is irrelevant to past evidence. The frontend creates a short-lived blob URL for the private download, displays local retry feedback and preserves keyboard focus. The read-only preview supplies a clearly labeled synthetic document.

Your facts uses the same PDF download helper for current resume/transcript selection. Each request binds its expected content hash and the backend rechecks selection after reading. Static controls preserve unsaved fact edits, reflect upload/withdrawal availability and retain local loading/retry feedback.

Employer-password migration is a separate disclosure in Needs you, with export and destination-import steps. It reuses the CLI's encrypted-transfer contract, requires a paused confirmed applicant with matching history and never displays stored native passwords. Temporary transport files contain encrypted bytes only, secret fields clear after completed requests and local pending state holds worker-start controls. The demo keeps these forms disabled.

Backup checks live beside the history download in Preferences. The upload is streamed into private temporary storage and tested through the normal new-directory restore validator; it never replaces or pauses the active workspace. A stable report shows only confirmed identity and fixed full-ledger/file counts. Selecting another archive clears the previous report, and upload failures provide a local retry.

Spreadsheet posting imports use a local file, read-only full validation and a separate Add checked postings action. The preview binds the upload's SHA-256, names the new/existing counts and explicitly limits the visible sample to ten rows. Selecting another file clears the review. CSV errors are line-specific and leave all rows unsaved; failed saves keep the checked preview for retry. Fields remain disabled while a request is pending. The blank template contains only supported headers, with a UTF-8 BOM for common spreadsheet tools.

Saved opportunity views sit beside the ledger filters in a disclosure. Names, search text, status and sorting stay in the private ledger, with a maximum of 20 views and case-insensitive unique names. Opening starts from page one and restores previous filters/results if loading fails. The view manager preserves unchanged card nodes during polling, keeps unsaved forms elsewhere intact and returns keyboard focus to usable controls after updates/removal. New and replacement filters require explicit actions; no employer records or submission controls change.

Find a tool is available from the top bar and Ctrl/⌘ K. Its static task catalog searches names, plain descriptions and synonyms without querying private content or a model. Common tasks form the initial list; filtered results and an empty state use ordinary keyboard-accessible buttons. Arrow keys, Home/End, Enter and Escape work alongside native dialog focus trapping. Choosing a result changes the visible section, expands containing disclosures and focuses a neutral destination; it never clicks an action button. Closing restores the prior control, and switching from posting details keeps dialog scroll locking consistent.

Saving a form temporarily holds its controls and shows a live working message. Values are captured before controls are disabled, and repeat submissions are suppressed until the request finishes. Other sections remain usable; completing a save only releases focus inside its own form. Failed saves retain drafts, polling respects pending forms, and keyboard focus returns to a usable control when the request ends.

Preferences keeps Save preferences and Discard changes in a sticky bar within the form. Discard is available only for an unsaved editable workspace and restores the last loaded saved values without a request. Focused fields scroll above the bar so keyboard navigation remains unobscured. Unsaved facts or preferences, including pending saves, trigger the browser’s normal leave-page warning; internal workspace navigation keeps drafts without prompting. No draft text is persisted in browser storage.

Refresh requests made while source paging or saved-view operations hold the current view are coalesced and run after that operation finishes. A form save waits for this fresh state before releasing its controls. Source page success moves focus to the library only if the user is still working in that section; switching to another editor preserves focus and drafts. Failed page loads release the same queued refresh and restore usable controls.

Your facts has a local Discard fact edits action beside Save confirmed facts. It restores the last loaded confirmed values and extracted proposals, resets the confirmation checkbox, preserves optional-field visibility and returns focus to Save. It shares the preference form’s draft availability rules, while each discard action leaves the other form’s unsaved edits intact.

Opportunity details includes an on-demand private notes editor. A separate notes script keeps text out of the polling snapshot, application sources and browser storage. Drafts survive dialog changes in page memory; clean cached entries are bounded to 100, while unsaved entries are retained. Pending saves freeze their own form, explicit reload/discard clears a draft only after a successful read, and stale revisions report a conflict without overwriting either copy. Empty saves clear text while retaining a revision. The read-only demo exposes the editor but disables saves.
